# Protocol — three decision systems bakeoff

**Bakeoff id:** `flybrain-jev-laya-2026-09` (see `lockfile.json`)

Do not edit this file mid-run. If a rule is wrong, add a dated **Amendment** section at the bottom. Never rewrite history.

## 1. Scope

Decision-shaped calls only: situation text + fixed choice menu → chosen label + probabilities.

Not in scope: chat, free-form generation, typed-decisions fine-tunes for Laya, connectome weight-training (that is a separate fly-cast lab).

## 4. Questions

Byte-stable objects in `questions/`. For clinc150, build criteria from frozen `labels.json` (see `questions/clinc150.md`). Situation = row `text` only.

## 5. KPIs

Per arm × task:

- **accuracy** — fraction `choice == gold`
- **brier** — mean squared distance from one-hot gold over the menu
- **median_seconds** — median wall time per scored row
- **finishability** — `n_scored / n_planned` (planned = lockfile test rows unless a deliberate `--limit` smoke)

## 6. Cost stop (Jev)

Default: stop if metered input spend exceeds `$1.00` at `$0.042 / 1M` input tokens (see lockfile). Record `stopped` reason in the summary.

## 7. Publish / compare rule

A **valid reproduction** cites:

1. `lockfile.json` bakeoff id + hashes verified green  
2. Question objects used (or regenerated identically for clinc150)  
3. Arm versions (Jev model id, Laya checkpoint + cfg, Flybrain recipe commit)  
4. Summaries with `n_scored` / `n_planned`

Matching Decision Science Corp’s published percentages is **not** required for validity. Drift is interesting; silent hash drift is invalid.
